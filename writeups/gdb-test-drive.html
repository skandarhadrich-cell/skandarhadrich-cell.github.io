GDB Test Drive — Skip the Sleep, Take the Flag

picoCTF's warm-up for GDB users. You're handed a Linux binary whose main function sleeps for a ridiculous amount of time before printing the flag — and the challenge description literally hands you the debugging session that skips it. Goal: realize the hint is a complete roadmap, not a nudge to "think deeper".

1 · The Description Is the Solution

The binary is a 64-bit ELF (PIE build). The description gives the exact commands — run them verbatim, don't overthink it.

chmod +x gdbme
gdb gdbme
(gdb) layout asm
(gdb) break *(main+99)
(gdb) run
(gdb) jump *(main+104)

layout asm opens the TUI disassembly view so you can watch the program counter walk through main while you drive it.

2 · Why These Offsets

In main, right after decrypting the flag into a stack buffer, the program calls sleep. The literal 0x186a0 milliseconds is 100000 seconds — about 27 hours — so a plain run would just hang. The breakpoint at main+99 lands on that sleep call.

# main(), roughly
rotate_encrypt(buf);      # decode flag into stack buffer
sleep(100000);             # main+99: this is where we break
puts(buf);                 # main+104: jump here to land on the print

The leading * matters: it tells GDB that (main+99) is an address expression, not a linespec — otherwise the breakpoint is set at the wrong thing.

3 · Skip the Delay With jump

Once run stops inside sleep, jump *(main+104) rewrites RIP to the instruction right after the call. GDB then resumes from there, and because the stack buffer still holds the decrypted flag, the very next thing to run is the puts that prints it.

(gdb) jump *(main+104)
# program resumes past the sleep and exits cleanly with the flag on stdout

5 · Retrospective

Key ideas: jump *addr sets RIP directly and resumes — a cheap way to skip a runtime delay without patching the binary on disk; and when a challenge description hands you exact GDB commands, the challenge is about following them precisely. The symbolic form *(main+99) also survives PIE relocation, where a hardcoded address would not.
